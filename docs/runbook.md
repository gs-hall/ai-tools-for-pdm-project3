# Runbook

Как запускать, сбрасывать и проверять приложение и что делать при неполадках. Команды для macOS; на Windows вместо `.venv/bin/python` — `.venv\Scripts\python.exe`.

## Обычные операции

| Задача | Команда |
|---|---|
| Запустить приложение | `.venv/bin/python app.py` → http://127.0.0.1:8000 |
| Сбросить базу к стартовым данным | `.venv/bin/python -m dispatcher.db reset` или кнопка «Сбросить данные» |
| Разобрать все новые дела | `.venv/bin/python scripts/run_queue.py` |
| Разобрать одно дело | `.venv/bin/python scripts/run_queue.py RC-6014` |
| Пересобрать таблицу результатов и выгрузку журнала | `.venv/bin/python scripts/run_queue.py --report` |
| Посмотреть доступные модели | `.venv/bin/python scripts/run_queue.py --models` |
| Прогнать другую модель в отдельную базу | `AI_MODEL=claude-haiku-5-5 DISPATCHER_DB=data/runtime/haiku.sqlite .venv/bin/python scripts/run_queue.py` |
| Сохранить базу дампом | `.venv/bin/python -m dispatcher.db dump data/snapshot/dispatcher.sql` |
| Восстановить базу из дампа | `.venv/bin/python -m dispatcher.db restore data/snapshot/dispatcher.sql` |
| Запустить тесты | `.venv/bin/python -m pytest` |

## Работа менеджера

1. Выбрать дело в очереди, нажать «Разобрать агентом» (или прогнать очередь скриптом).
2. Прочитать факты, правила, причину остановки и заметку.
3. Подтвердить рекомендацию — клиент получит черновик агента (его можно поправить).
4. Изменить решение — комментарий и сообщение клиенту обязательны. Для ручного разбора решение выбирается всегда.
5. После «Запросить сведения» клиент отвечает в своём контуре, дело возвращается в «Новое» и разбирается заново.

## Где смотреть, что произошло

- Карточка дела → «Журнал»: вызовы функций, итог проверки, переходы состояний, решение менеджера, создание разрешения.
- Таблица `agent_runs`: сырой ответ модели и ошибки проверки по каждой попытке.

```
sqlite3 data/runtime/dispatcher.sqlite "SELECT case_id, model, guard_errors, fallback FROM agent_runs ORDER BY id"
```

## Неполадки

| Симптом | Причина | Что делать |
|---|---|---|
| «Access to localhost was denied», HTTP 403 на порту 5000 | На macOS порт 5000 занят приёмником AirPlay | Приложение слушает 8000; другой порт — `PORT=8080 .venv/bin/python app.py` |
| «Заполните AI_PROXY_URL и AI_PROXY_TOKEN в .env» (503) | Нет настроек модели | Заполнить `.env` по `.env.example` |
| «Модель недоступна: …» (502) | Сеть, неверный ключ или модель | Проверить `--models`; событие `LLM_ERROR` в журнале дела, ключ в нём замаскирован |
| `unexpected keyword argument` в `messages.create` | Версия SDK не совпадает с `requirements.txt` | Переустановить зависимости из `requirements.txt` |
| Модель объявлена устаревшей | Срок поддержки модели истекает | Выбрать новую через `--models` и указать в `AI_MODEL` |
| Дело ушло в «Ручной разбор» с пометкой «не прошёл серверную проверку» | Модель дважды вернула результат, который сервер не принял | Ошибки — в карточке и в `agent_runs.guard_errors`; решение принимает менеджер, можно разобрать заново |
| Решение «одобрить» отклонено (409) | По заказу уже выдано разрешение (P-4) | Закрыть как повторное или отказать |
| `database is locked` | Две записи одновременно | База в режиме WAL с ожиданием 5 секунд; если ошибка повторяется — не держать базу открытой в другом инструменте во время прогона |
| Ответ клиента отклонён (409) | Дело не ждёт ответа клиента | Ответ возможен только после «Запросить сведения» |

## Проверка, что секреты не утекли

```
git check-ignore -v .env
git grep -n "AI_PROXY_TOKEN=" -- ':!.env.example'
sqlite3 data/runtime/dispatcher.sqlite "SELECT count(*) FROM audit_log WHERE details LIKE '%' || '<начало ключа>' || '%'"
```

Первая команда должна показать правило из `.gitignore`, вторая — ничего, третья — 0.
