# Правила работы

Правила для разработчика и ИИ-ассистента, которые работают с этим репозиторием.

## Стартовые данные

- Не меняем ничего в `return-dispatcher-starter/`. Это входные данные и политика компании.
- Эталонные маршруты лежат только в `tests/fixtures/expected-routes.json`. Их читают только тесты и скрипт сверки; код агента и сервера их не читает, и это проверяет тест.

## Языковая модель

- Модель подключается через внешний API. Ответы не подменяются заготовленными строками.
- Модель получает только письмо, данные заказа, историю и политику — через серверные функции чтения, ограниченные своим делом.
- Модель не получает функций, которые меняют состояние, заказ или выдают разрешение.
- Каждый результат модели проходит серверную проверку. Если проверка не пройдена — одна повторная попытка с перечнем ошибок, затем ручной разбор.
- Системные инструкции модели хранятся в коде (`dispatcher/prompts.py`), а не собираются из входных данных.

## Решения и состояния

- Переходы состояний делает только сервер по таблице из `agent-spec.md`.
- Итоговый статус записывается только после решения менеджера.
- Учебное разрешение создаётся только в обработчике подтверждения одобрения.
- Клиентский контур получает только поля, разрешённые для клиента; список полей задан на сервере.

## Секреты и журнал

- Ключ API хранится только в `.env` (в git не попадает). В репозитории есть только `.env.example` без значений.
- Ключ не печатается в журнал, ответы API и интерфейс. Перед записью в журнал данные проходят очистку.
- Приложение не выполняет внешних операций, кроме запроса к API модели.

## Код

- Python 3.13, Flask, стандартный `sqlite3`, одна страница `static/index.html`.
- Без закомментированного кода, пустых файлов и неиспользуемых функций.
- Одинаковые конструкции выносим в функции, а не повторяем.
- Перед коммитом: `pytest` проходит, сервер запускается без ошибок в консоли.

## Коммиты

- Работаем в ветке `sprint_3`, в `main` — через pull request.
- Один шаг плана — один или несколько осмысленных коммитов с сообщением на русском.
- После изменений обновляем README, spec.md, agent-spec.md и материалы в `docs/`, если изменения их касаются.
