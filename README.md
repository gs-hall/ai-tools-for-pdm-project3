# Агент-диспетчер по возвратам

Учебный проект: ИИ-агент и его интерфейс для «Клевер Маркет». Агент разбирает обращения по возвратам, находит факты в заказе и истории, применяет политику компании, предлагает маршрут и готовит отдельные черновики для клиента и менеджера. Решение принимает только менеджер.

Стек: Python 3.13, Flask, SQLite (`sqlite3` из стандартной библиотеки), одна HTML-страница, языковая модель Claude через внешний API.

## Как это работает

1. Сервер импортирует стартовые данные из `return-dispatcher-starter/` в SQLite.
2. Менеджер запускает разбор. Модель читает заказ, историю и политику через серверные функции только для чтения и возвращает структурированный результат.
3. Сервер проверяет результат: маршрут, ссылки на правила, ограничения политики, текст черновика. Не прошёл — модель получает ошибки и одну попытку исправить, затем дело уходит на ручной разбор.
4. Менеджер подтверждает или меняет решение. Только после этого клиент видит ответ, а для одобрения создаётся учебное разрешение `RA-<номер дела>`.

Подробнее: [spec.md](spec.md), [agent-spec.md](agent-spec.md), [agent-decision-card.md](agent-decision-card.md).

## Установка

Нужны Python 3.13 и доступ к API модели. Ниже — через [uv](https://docs.astral.sh/uv/); подойдёт и обычный `venv`.

macOS / Linux:

```
cd ai-tools-for-pdm-project3
uv venv --python 3.13 .venv
uv pip install --python .venv/bin/python -r requirements.txt
cp .env.example .env
```

Windows (PowerShell):

```
cd ai-tools-for-pdm-project3
uv venv --python 3.13 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements.txt
copy .env.example .env
```

Заполните `.env`:

| Переменная | Что это |
|---|---|
| `AI_PROXY_URL` | Адрес агрегатора, через который идут запросы к Claude: `<AI_PROXY_URL>/anthropic/v1/messages` |
| `AI_PROXY_TOKEN` | Ключ доступа агрегатора |
| `AI_MODEL` | Модель, по умолчанию `claude-sonnet-5-5` |

`.env` не попадает в git. Ключ не пишется в журнал, ответы API и интерфейс.

## Запуск

```
.venv/bin/python app.py
```

Откройте http://127.0.0.1:8000. На macOS порт 5000 занят приёмником AirPlay, поэтому по умолчанию используется 8000; другой порт — переменная `PORT`. На Windows вместо `.venv/bin/python` — `.venv\Scripts\python.exe`.

При первом запуске база создаётся и заполняется автоматически. Сброс к стартовым данным — кнопка «Сбросить данные» или `python -m dispatcher.db reset`.

На странице:

- слева очередь из 16 обращений с маршрутом и решением;
- справа карточка дела: ход диалога, заказ, история, рекомендация агента с фактами, правилами и причиной остановки, заметка менеджеру, черновик клиенту и форма решения;
- переключатель «Менеджер / Клиент» показывает дело глазами клиента: только письмо, отправленные ему сообщения и статус. Рекомендацию и черновик сервер клиенту не отдаёт.

## Посмотреть результат без ключа API

Состояние базы после прогона 16 дел и решений менеджера сохранено SQL-дампом. Восстановите его и откройте страницу — рекомендации, решения, разрешения и журнал будут на месте:

```
.venv/bin/python -m dispatcher.db restore data/snapshot/dispatcher.sql
.venv/bin/python app.py
```

Демо главного сценария — [docs/demo.gif](docs/demo.gif).

## Прогон очереди

```
.venv/bin/python scripts/run_queue.py
```

Скрипт разбирает все новые дела, сверяет маршруты с эталоном `tests/fixtures/expected-routes.json` и пишет таблицу [docs/results.md](docs/results.md) (маршрут, решение, разрешение, состояние до и после, ссылка на журнал) и выгрузку журнала [docs/audit-log.md](docs/audit-log.md). Эталон читает только этот скрипт и тесты — не агент и не сервер.

Другие режимы: `RC-6001` — одно дело, `--report` — только таблица, `--models` — какие модели Claude доступны.

## Тесты

```
.venv/bin/python -m pytest
```

42 теста проверяют серверную часть без обращения к внешнему API: проверку результата модели, переходы состояний, human gate и разрешение, права ролей, клиентский ответ без рекомендации, очистку журнала, режим базы и дамп. Сводка проверок — [docs/checks.md](docs/checks.md).

## Структура

```
app.py                     Flask API и раздача страницы
dispatcher/
  db.py                    схема SQLite, импорт и сброс
  policy.py                разбор политики на правила P-n и C-n
  tools.py                 функции чтения для модели и вычисляемые факты
  prompts.py               системные инструкции модели
  llm.py                   подключение к API и цикл вызова функций
  guard.py                 серверная проверка результата модели
  workflow.py              состояния дела, разбор, решение менеджера
  views.py                 что видит менеджер и что видит клиент
  audit.py                 журнал с очисткой секретов
static/index.html          страница
scripts/run_queue.py       прогон очереди и сверка с эталоном
tests/                     тесты и эталон
docs/                      результаты, журнал, проверки, runbook, карточка кейса, скриншоты, демо
data/snapshot/             SQL-дамп базы после прогона
return-dispatcher-starter/ стартовые данные и политика (не меняются)
```
